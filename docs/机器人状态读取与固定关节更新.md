# 机器人状态来源与躯干反馈同步

状态话题由节点参数 `joint_states_topic` 指定，默认 `/joint_states`。

节点订阅 `sensor_msgs/msg/JointState`，`_on_joint_state` 按 `name` 对应的 `position` 更新 `_joint_map`。这是逐关节缓存：消息只带部分关节时，其余关节保留最近一次收到的值。OPT 规划请求通过 `_current_curobo_state` 复制这个字典，先同步反馈几何，再按规划器的关节名称顺序生成 cuRobo JointState 起点。MPC 从同一状态回调收位置、速度和时间，并在跟踪更新时同步模型。

TF 负责目标位姿、点云的坐标转换；URDF 负责关节连接、轴和零位变换。它们与关节反馈各有职责。当前状态来源是 ROS 话题缓存，而非规划时临时向控制器查询。

`fixed_state.py` 新增固定关节反馈更新器。当前 Lycus 覆盖 `Calf_joint`、`Thigh_joint`、`Waist_joint`、`Chest_joint`、`Neck_joint`、`Head_joint`。这些关节仍作为不参与优化、不下发的固定自由度，但每次反馈到来后的模型同步采用实际角度，取代此前始终使用配置零位的行为。

- OPT：更新 IK、TrajOpt、PRM 及辅助运动学副本；FCL 使用同一份已解析固定关节状态。固定姿态变化会清理 PRM 缓存。
- MPC：更新主求解器、内部 IK、独立构型运动学及可达性 IK 的运动学副本，并维护 `locked_joints` 状态。
- 原地写入 fixed_transforms 和 lock_jointstate，不重建求解器、不改变活动关节数、不更换 CUDA graph 使用的张量地址。
- 未改静态场景合并和缺失主动关节反馈的默认值策略。
