# 本体点云过滤

## 按规划组选择过滤范围

OPT 使用请求的 group_name；MPC 使用当前单臂/双臂目标模式，预热使用预热模式。
- left_arm：只删除左臂及其后代夹爪/工具的点云。
- right_arm：只删除右臂及其后代夹爪/工具的点云。
- both_arms：删除两臂及其后代夹爪/工具的点云。

按 URDF 关节拓扑识别后代，不依赖 link 名称前缀；范围仍受 collision_link_names 约束。躯干、头部以及单臂模式下另一只手臂不参与删点。计算手臂位姿仍需其上游躯干关节反馈，但不再要求另一臂反馈。本体过滤不会改变规划器原有全身碰撞检查范围。

掩码缓存包含规划组；MPC 切换规划组时即使点云帧不变也重新加载场景，避免复用另一组的删点结果。

入口为 planning/self_filter.py，由 motion_planning_node.py 和 planning/mpc_follow.py 共用。

## 参数
- self_filter_mode: off（默认关闭）、observe（发布候选结果，规划保留原点）、apply（实际删除）。
- self_filter_padding: 默认 0.01 m，允许 0 到 0.05 m。
- self_filter_max_processing_ms: 默认 100 ms，几何处理超时则整帧不删点。这是协作式检查，不是硬实时上限，单次原生库调用无法中断。

## 流程
读取 XYZ → 有限值/距离筛选 → 最新可用 TF 转到 base → 范围裁剪 → 本体过滤 → 降采样 → 原有排除盒 → OPT/MPC 碰撞场景。
使用当前关节反馈快照计算本体姿态，不读取点云时间戳做对齐或插值；旧包和零时间戳点云均可处理。缺少必要关节或数值无效时保留原始点。
使用配置 collision_link_names 的 URDF collision mesh，先包围盒筛选，再顶点距离/FCL 球与三角形相交，封闭 mesh 补充内部判断。非封闭 mesh 仅删除表面余量内点。
反馈缺失、异常、超时均保留本次输入。apply 全删时走空场景处理；OPT 配置静态场景时拒绝直接清空混合场景。
缓存要求同一消息、相同关节姿态/余量及点数组。过滤对象不修改规划器 FCL 对象姿态。

## 观察与限制
启动时将 self_filter_mode 设为 observe，查看 /curobo/self_filter/input、removed、environment；这些话题在有订阅者时发布。
确认模型和标定后可启动 apply。配置默认仍为 off。
覆盖范围取决于 collision_link_names 和对应 collision 几何，不自动覆盖未配置部件；余量可能删除紧贴本体的环境点。
离线测试不能证明标定精度或现场吞吐。100 ms 是初始预算，需根据实测耗时调整。

## 观察、回退和 MPC 重试
observe 单独计算可视化分类，规划输入仍走 off 的原有流程：相机坐标系降采样 → 最新 TF 变换 → 裁剪。过滤异常时也回到该流程，保持规划点数组一致。
apply 成功时才使用过滤后的点云并降采样。point_filter 回调返回原数组对象表示观察或回退，返回新数组表示已应用过滤。
MPC 分别记录已加载帧和待重试过滤帧。缺关节、超时或几何异常后，首次加载未过滤场景；后续 tick 重试同一帧，连续失败不重复重建该场景，成功后更新场景并结束重试。每次尝试仍受几何预算约束。TF 查询失败不标记帧已加载。
